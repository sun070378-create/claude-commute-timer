# 通勤碼表

> 這個專案由 [Claude Code](https://claude.com/claude-code) 協助製作。

讓大家自己記錄搭淡海輕軌、安坑輕軌、台北捷運時的**進站、等車、乘車、轉乘、出站**時間，集中起來統計出真實的通勤時間。

本站不是臺北捷運公司、新北捷運公司或任何政府機關的官方網站。

## 怎麼用？

1. 選起點站、終點站，按「準備出發」
2. 刷卡進站按「刷卡進站了」→ 到月台按「開始等車」→ 車來按「上車了」
3. 轉乘時，下車按「要轉乘」，到下一個月台再按「開始等車」（車剛好在月台就按「直接上車」）
4. 到站後按「下車，走向出口」，刷卡出站再按「刷卡出站了」
5. 確認時間，按「送出」

忘了按「刷卡進站」也沒關係，可以直接從「開始等車」開始；出站時也可以選「不記錄出站時間」。缺了進站或出站的紀錄，只是不列入「閘門到閘門」的統計。

**常用路線**：每天走的路線按「把這條路線存成常用路線」，之後首頁一鍵出發，去程、回程都有。

**到站／離站方式**（選用）：在「更多選項」選騎腳踏車、開車等，碼表會多記一段「前往車站」或「前往目的地」。存成常用路線後，回程會自動對調（上班騎車到站＝下班騎車回家）。這兩段和住家位置有關，**只存在自己的手機，不會上傳**。

**轉乘資訊**（選填）：送出前可以選每次轉乘在哪一站，並標記「用跑的」或「到月台時車剛好開走」。同一條路線下次會自動帶入，反方向也會倒過來帶入。

**我的路線比較**：「我的紀錄」會把同一個起訖點依到站方式和轉乘站分開，列出各種走法的中位數，標出最快的走法。

**備份紀錄**：「我的紀錄」可以匯出備份檔，換手機時在新手機匯入，紀錄、常用路線和裝置代碼都會帶過去。

中途關掉螢幕或切到別的 App 都沒關係，時間是用按下按鈕的時刻計算的。按錯了可以「復原上一步」。

**沒有網路也能用**：網站打開過一次之後，沒有網路也能打開。送出時沒有網路，紀錄會先存在手機，連上網路後自動補送；「我的紀錄」會標示還沒送出的紀錄。

統計頁會依路線和時段（平日尖峰 7–9、17–19 點／平日離峰／假日，以刷卡進站的時刻判定）顯示**中位數**和「一半的紀錄落在幾分到幾分」，用中位數是為了不被少數極端值（例如遇到故障）拉歪。統計分成兩種：

- **月台到月台**：等車＋乘車＋轉乘，所有紀錄都有
- **閘門到閘門**：再加上進站、出站，和悠遊卡進出站是同一個基準；只用有記錄進出站的紀錄計算

## 隱私

網站上的〈隱私與使用說明〉有完整說明，重點如下：

- **上傳的資料最小化**：只上傳統計需要的部分。各段時長精確到秒，但時刻只保留到分鐘；到站／離站不上傳；備註只有使用者勾選時才上傳
- **原始紀錄不公開**：大家只看得到資料庫算好的統計結果，原始紀錄也不在資料授權的範圍內
- **5 人門檻**：同一條路線、同一時段要有 5 個以上不同的裝置記錄才會顯示，避免從統計反推出個人的通勤時間
- **可以申請刪除**：「我的紀錄」頁面會顯示自己的裝置代碼，附上代碼透過 [GitHub Issues](https://github.com/sun070378-create/claude-commute-timer/issues) 或 email（sun070378@gmail.com）請維護者刪除

資料庫也會在收到資料時再檢查一次：站名必須在車站清單內、時刻四捨五入到分鐘、移除到站／離站、各段秒數重新計算，舊版網頁送來的資料也一樣。

## 相關專案

用乘客資料估算交通時間的服務不只這個，各自目的不同：

- **Transit**（GO 功能）、**Moovit** 等國外 App 也會用乘客分享的資料推估車輛位置或行車時間，主要目的是即時導航，或製作城市層級的大眾運輸報告。
- **官方 App**（例如台北捷運Go）的資訊來自營運系統，例如時刻表和列車位置，不是乘客實際花費的時間。

本專案的特點是：乘客自己實測、以閘門到閘門為基準、把等車和轉乘拆開計算，並公開彙總統計。之後如果使用交通部 TDX 等開放資料，會依其規定標示資料來源。

### 新增或修改車站

資料庫會擋掉不在車站清單裡的站名，所以車站清單有兩份：`stations.js`（網頁用）和 `supabase/schema.sql`（資料庫用）。改完 `stations.js` 後：

1. 執行 `node scripts/check-stations.js --write`，自動更新 `schema.sql` 裡的清單
2. 到 Supabase 的 SQL Editor 重新執行整份 `schema.sql`

## 先在自己電腦試用

直接雙擊 `index.html` 就能用。還沒設定資料庫時是「本機模式」，紀錄只存在自己的瀏覽器裡。

## 讓大家的資料集中起來（設定 Supabase，免費）

1. 到 <https://supabase.com> 註冊，建立一個新專案（Region 選 Tokyo 或 Singapore 比較快）
2. 左邊選 **SQL Editor**，把 `supabase/schema.sql` 的內容整段貼上，按 **Run**。整份可以重複執行，之後 `schema.sql` 有更新時，一樣整段重新執行就會升級，既有資料會保留（同一台裝置、同一個出發時刻重複送出的紀錄，只會留下一筆）
3. 左邊選 **Project Settings → API**，複製：
   - **Project URL**（像 `https://abcdxyz.supabase.co`）
   - **anon public** key（很長一串）
4. 貼到 `config.js` 的引號裡，存檔

anon key 本來就是設計給網頁公開使用的；資料表已設定成「任何人只能新增，不能讀取原始紀錄、修改或刪除」，而且會擋掉不合理的資料（例如超過 4 小時、站名不存在、資料過大）。

**注意**：把 `schema.sql` 推到 GitHub 不會改到線上的資料庫，一定要到 SQL Editor 重新執行才會生效。

## 放上網路（GitHub Pages，免費）

1. 到 repo 的 **Settings → Pages**，Source 選 **Deploy from a branch**，Branch 選 `main`、資料夾選 `/ (root)`，按 Save
2. 等一兩分鐘，網址會是 <https://sun070378-create.github.io/claude-commute-timer/>

之後更新網站，使用者下次在有網路的時候打開，就會自動換成新版。

把這個網址傳給朋友，或在 PTT、Dcard、臉書社團分享，大家就能一起記錄了。手機瀏覽器選「加入主畫面」，用起來就像 App，也會有自己的圖示。iPhone 加入主畫面後，主畫面的通勤碼表和 Safari 的紀錄是分開的，可以用「我的紀錄」的匯出、匯入把紀錄帶過去。
